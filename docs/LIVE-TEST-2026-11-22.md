## memory 组

### writeIndex

`memoryEnabled=false` 时，`agents_memory` 调用成功，但 `AGENT_CONTEXT_INDEX.md` 的 SHA256 保持 `6734caecd40d3a40f22499787e94e8f4be055e1545127e9003e87d1c4989c7dd` 不变；普通写入仍成功。恢复 memory 组后，`agents_index search` 找到该测试条目（seq 28696），索引与 `AGENT_CONTINUITY.md` 均未被删除。

已知文案不一致：memory 组关闭时 `agents_memory` 的成功提示仍声称写入了索引，实际被 `writeIndex` 条件抑制。源码在 0.8.1 已冻结，本次只记录，不在本轮改代码。

### recordGate

- `memoryEnabled=false` 且 recordGate 关闭：写 `.tmp/guard-live2/record-off.txt` 成功。
- 恢复 memory 组、recordGate 开启：同一 record-intent 写入被拒绝。
- 调用 `agents_memory` 记录一条 requirement（seq 28946）后，写入放行。

### recallGate

- recallGate 关闭：`session_search` 没有 Guard 拒绝；搜索本机在 30 秒时超时，这是搜索工具自身超时，不是 Gate。
- recallGate 开启：`session_search` 被拒绝，提示先调用 `agents_index`。
- 多语句 `run_code` 内的 `agents_index` **不会**解锁；`lib/core.mjs:833` 只对直接调用或“恰好一条安全 run_code 调用”记录 `agentsIndexSeq`。
- 改成单独一次 `return await tools.agents_index({action:"search",...})` 后解锁；下一次 `session_search` 执行并在 30 秒超时，没有 Guard 拒绝。

### indexGate

`memoryEnabled=false`（indexGate 关闭）时，一个无效的 `compress` 请求到达了 compress 工具，Guard 没有报 indexGate；compress 返回：

```text
[Compression FAILED: no valid ranges parsed (kind=no-valid-ranges, dropped=1)]
```

没有上下文被压缩。indexGate 开启且故意让审计失败的拦截路径本次未测。
